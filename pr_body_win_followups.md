## Summary

Follow-ups found when the test suite was run on the ZBook (Windows 11, Windows PowerShell 5.1, Python 3.13.15).

- **Edge auth test.** `test_ordinary_close_keeps_fast_reconnect_and_rate_limits_the_warning` failed on Windows with 2 connects instead of 3. A refused TCP connect takes about 2 s on Windows and `localhost` resolves to `::1` first, so each reconnect took about 3 s instead of 1 s. The test now serves and dials `127.0.0.1`. The window (3.5 s) and the count (at least 3) are unchanged, so the test proves the same thing on macOS and Linux. The product edge URL already defaults to `127.0.0.1` (`flightrisk/launcher/settings.py`, `edge_url`), so no product change was needed.
- **Installer MiDaS tests.** The `[windows]` cases only looked for `pwsh` and skipped on a machine with only `powershell.exe`. They now fall back to `powershell.exe` on win32. On Windows the fake venv uses the layout install.ps1 expects (`venv\Scripts\python.exe`, an empty placeholder for the layout check) plus a `python.cmd` that records the call, and the snippet points `Get-VenvPython` at the `.cmd` because an `.exe` cannot be a script. On macOS the cases still skip when no PowerShell is present. I read `installer/windows/install.ps1` for PowerShell 7 only syntax (`??`, ternary, `&&` or `||` chains, `-Parallel`, nested `Join-Path` arguments) and found none, so the script needed no change. This is a read-through only; it has not been run under 5.1 from here.
- **plan_store.** `os.replace` can raise `PermissionError` (WinError 5 or 32) on Windows while another handle holds the file. `save_plan` now retries up to 5 times, 75 ms apart, only for `PermissionError` on win32, then re-raises. The dashboard already reports "the plan could not be written" for that error. Four new tests simulate the error: retry then success, retry exhausted with no temp file left, no retry off Windows, no retry for other errors.
- **Restart tests.** `test_restart_replaces_the_process`, `test_restart_writes_a_new_log_file_and_keeps_the_old_one` and `test_restart_through_the_api` inject `windows=False`, which selects the POSIX spawn and stop path (`start_new_session`, signals). That path cannot work on a real win32 host, so they are now skipped there with a reason (Windows refuses an edge restart by design). The same skip is on the other three tests in `test_launcher_processes.py` that inject `windows=False` and spawn or stop real processes. The refusal itself is covered on every platform: the existing manager test uses `windows=True`, and the new `test_restart_of_an_edge_is_refused_on_windows` checks `can_restart` and the 409 with `WINDOWS_EDGE_RESTART_REFUSED` through `/api/restart` without spawning anything.
- **Leak checks.** The Windows handle count moves by 2 or 3 for reasons that are not leaks, so on win32 `tests/support/leaks.py` reports a handle delta only above 8 (`WINDOWS_HANDLE_NOISE`). Descriptor checks on macOS and Linux are unchanged and exact. A test covers both platforms.
- **Mobile contract fixture.** `test_regenerated_fixtures_match_the_committed_files` failed on the ZBook because of `library_versions` only (venv had flask-socketio 5.7.0, python-engineio 4.14.0, python-socketio 5.17.0; the fixture records 5.6.1, 4.13.3, 5.16.3). That is dependency drift, not CRLF. The comparison now ignores `library_versions`, and a new test checks that the versions are recorded and that the Engine.IO open frame and `EIO=4` still match. The Windows lock (`installer/locks/windows-x64-ground.txt`) and the macOS lock both pin the committed versions, so the ZBook venv is simply newer than its lock; it was not built from the lock.
- **Task destroyed while pending.** `AsyncBridge.stop_loop` now cancels and awaits every other task on the loop (2 s bound, skipped when called from the loop thread, never raises) before stopping it, so no task is left pending when the loop closes. This was the source of the asyncio `Task was destroyed but it is pending!` ERROR and the RuntimeWarning caught in `test_sync_send_before_connect_is_quiet`. A regression test fails without the fix on macOS and passes with it. That test also now dials `127.0.0.1`.
- **Fake fleet tests.** `_pid_alive` used `os.kill(pid, 0)`, which terminates the process on Windows; it now uses psutil there (skipping with a reason if psutil is missing). Cleanup no longer calls `os.killpg` on Windows. `test_terminate_all_leaves_no_orphans` does not assert on the grandchild on Windows, which has no process groups to signal. `test_ctrl_c_tears_down_the_launched_processes` is skipped on win32 with a reason (it needs POSIX SIGINT delivery).
- **Lint.** Removed two unneeded `# noqa: E402` in `scripts/check_wildcard_guard.py` (RUF100) and fixed the B023 loop-variable capture in `tests/test_tello_local_ip.py`.
